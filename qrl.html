FCC-ee QRL Cryogenic Flow Model

As part of my work in the cryogenics group at CERN, I am developing a Python tool that models the helium mass flow and pressure distribution along the QRL (cryogenic distribution line) for the proposed FCC-ee accelerator. The goal of the model is to map out the mass flows, pressures, temperatures, and enthalpies along the line for a given set of initial conditions, providing inputs for the sizing and design of the future cryogenic distribution system.

Background

The QRL feeds helium to the dozens of superconducting radiofrequency cryomodules along the accelerator tunnel. The 400 MHz and 800 MHz cryomodules operate at different conditions, so six helium lines run in parallel inside the transfer line:

  • Line A: 2 K helium supply to the 800 MHz cryomodules
  • Line B: 2 K helium return from the 800 MHz cryomodules
  • Line C: 4.5 K helium supply to the 400 MHz cryomodules
  • Line D: 4.5 K helium return from the 400 MHz cryomodules
  • Line E: thermal-shield supply (~45 K)
  • Line F: thermal-shield return (~55 K)

Purpose of the Code

The model calculates the behaviour and changes in the helium properties at each mixing/diverging node along one side of the QRL. A node is a location where a cryomodule, return module, or QUI is connected.

Properties tracked with the code: pressure [bar], temperature [K], enthalpy [h, J/g], mass flow [g/s], velocity [m/s], density [rho, kg/m3], and flash [%].

Step 0 - Define the Calculation Sequence

The calculation starts from known or assumed boundary conditions at the return-module end and progresses node by node, or cryomodule by cryomodule, towards the QUI. The properties inside each cryomodule are also known. For each QRL segment, the code:

  • calculates the heat added to the helium and the pressure drop along the pipe;
  • updates pressure, enthalpy, temperature, and density at the next node;
  • calculates flash and required mass flow when a cryomodule is connected; and
  • repeats the process until the properties have been mapped along the complete line.

A node-by-node calculation is important because the helium state before a JT valve affects the flash fraction. The flash fraction changes the required mass flow, which in turn affects flow velocity and pressure loss.

Step 1 - Build the QRL Layout

The physical arrangement is defined as a set of cryomodule blocks. For each block, the user specifies the cryomodule type, number of modules, spacing between jumpers, and connected QRL lines. The build_layout() function converts those inputs into:

  • x_nodes, an ordered list of positions for the QUI, cryomodules, and return module; and
  • a line-specific Boolean mask that identifies where helium mass enters or leaves each line.

This keeps the calculation flexible when the number, order, or spacing of the 400 MHz and 800 MHz cryomodules changes.

Step 2 - Map Conditions Node by Node

The node_flow_mapping() calculation treats the helium lines in supply/return pairs and marches from the return module toward the QUI. The boundary pressure, temperature, enthalpy, and mass flow are first assigned at the return-module node.

For every pipe segment, the code calculates pressure loss from the local flow conditions and pipe geometry. Distributed heat inleak is converted into an enthalpy change, after which the pressure, enthalpy, temperature, and density are updated at the next node.

When the line mask is true, the cryomodule heat load sets the required liquid flow. The code then calculates the JT flash and upstream mass flow. Return lines combine incoming streams using mass and energy balances so that different inlet enthalpies are represented correctly.

Step 3 - Plot and Tabulate the Results

The same process is repeated for all six lines. The reporting functions then generate profiles of pressure, temperature, enthalpy, mass flow, velocity, density, and flash along the QRL, together with compact tables for the most important nodes.

Conclusion

The model takes a cryomodule layout, estimated heat loads for each cryomodule, and a set of boundary conditions, then calculates the estimated QRL properties at each node (where a cryomodule is connected). It calculates how the mass flow, temperature, and pressure change throughout the QRL. This information is useful for sizing the rest of the refrigeration system because it helps estimate the conditions required at the QUI.

This model provides a first-pass estimate of the properties expected in a theoretical QRL. The modularity of the code is also useful because the FCC baseline is constantly changing and evolving. Further improvements are still needed, including accounting for losses across the Joule–Thomson valves, improving the return-model behaviour, and adding other effects. Further validation of the model, including comparison with current LHC data, is also still needed.
